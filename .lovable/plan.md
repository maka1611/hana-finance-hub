
# API для доступа нейросети ко всей базе данных

Цель: дать ИИ-ассистенту возможность читать абсолютно все данные (клиенты, контракты, платежи, инвесторы, средства компании, аудит и т.д.) для аналитики и сверки. Доступ — только на чтение, с двухуровневой защитой.

## Двухуровневая защита

1. **Уровень 1 — секретный API-ключ** (`AI_READONLY_API_KEY`, генерируется автоматически, хранится в секретах). Передаётся в заголовке `Authorization: Bearer <key>`.
2. **Уровень 2 — подпись запроса HMAC** (`AI_READONLY_HMAC_SECRET`). Каждый запрос подписывается: `X-Signature: hmac_sha256(secret, timestamp + ":" + path + ":" + body)` + заголовок `X-Timestamp` (окно ±5 минут, защита от повторов).

Дополнительно: rate-limit (например, 60 запросов/мин по IP+ключу), запись всех обращений в `admin_audit_log`, поддержка только GET/POST для чтения — никаких записей.

## Эндпоинты (под `/api/public/ai/*`)

Все маршруты — TanStack server routes, читают через `supabaseAdmin` (после проверки ключа + HMAC).

- `GET /api/public/ai/schema` — список всех таблиц и их колонок (для самоописания нейронке).
- `GET /api/public/ai/tables/:table?limit=&offset=&since=&format=json|csv` — постраничное чтение любой таблицы из whitelisted-списка (все public-таблицы проекта). Поддержка фильтра по `updated_at >= since` для инкрементальной синхронизации.
- `GET /api/public/ai/export/full?format=json|zip` — полный дамп всей базы:
  - `json` — один файл со всеми таблицами,
  - `zip` — архив, каждая таблица отдельным CSV.
- `POST /api/public/ai/query` — параметризованный безопасный запрос: тело `{ table, select, filters, order, limit }`. Без сырого SQL — конструктор фильтров поверх PostgREST, чтобы исключить SQL-инъекции.

Все ответы включают мета: `generated_at`, `row_counts`, `next_offset`.

## Доступ из кабинета владельца

В разделе админки добавится страница «API для ИИ»:
- показ статуса ключа и HMAC-секрета;
- кнопка ротации (генерирует новые секреты);
- кнопка «Скачать полный дамп» (JSON и ZIP-CSV) — вызывает тот же эндпоинт изнутри сессии owner без необходимости в ключе;
- журнал последних обращений по API;
- инструкция для подключения нейронки (пример curl + подписи).

Доступ к странице — только `has_role(owner)`.

## Что НЕ входит

- Никаких write-операций через API.
- Никакого экспорта `auth.*`, `storage.*` и других системных схем — только `public`.
- Колонки с особо чувствительными данными (`client_secrets`) — исключаются из выдачи по умолчанию; владелец может явно включить их флагом `include_secrets=true` в полном дампе.

## Технические детали

- Файлы: `src/routes/api/public/ai/schema.ts`, `tables.$table.ts`, `export.full.ts`, `query.ts`; helper `src/lib/ai-api/auth.server.ts` (проверка Bearer + HMAC + rate-limit + audit-log); `src/lib/ai-api/exporter.server.ts` (сбор всех таблиц, CSV/ZIP через `jszip`).
- Секреты: `AI_READONLY_API_KEY` и `AI_READONLY_HMAC_SECRET` — `generate_secret` (64 символа каждый).
- Кабинет владельца: `src/routes/_authenticated/admin.ai-api.tsx` + ссылка в `AdminSidebar.tsx` (только для роли `owner`).
- Аудит: новая таблица `ai_api_access_log` (timestamp, endpoint, ip, key_id, status, rows_returned) с RLS «только owner читает».
- Без изменений существующей бизнес-логики, контрактов, аналитики.

После одобрения плана я создам миграцию для `ai_api_access_log`, сгенерирую секреты и добавлю эндпоинты + страницу в кабинете владельца.
