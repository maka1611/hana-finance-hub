
# План: email-уведомления с собственного домена

## Что получит пользователь

1. **Письма от своего домена** (например `noreply@notify.вашдомен.ru`) вместо стандартных — выше доверие и доставляемость.
2. **Брендированные auth-письма**: подтверждение регистрации, сброс пароля, magic link, смена email — в едином стиле приложения.
3. **Письмо при оформлении рассрочки** — клиент получает на почту: товар, цена, первоначальный взнос, срок, ежемесячный платёж, итоговая сумма, дата первого платежа, ссылка на личный кабинет.
4. **Письмо новому клиенту** — если админ оформил рассрочку клиенту, которого раньше не было в системе: логин (email), временный пароль + полная сводка по рассрочке в том же письме.

## Шаги реализации

### 1. Настройка email-домена
Откроется диалог настройки отправляющего домена. Нужен домен, доступ к DNS-провайдеру (Lovable делегирует поддомен `notify.<домен>` на свои NS-записи). После добавления — DNS верифицируется автоматически, рассылка стартует сразу после успешной проверки.

### 2. Инфраструктура писем
Автоматически разворачивается очередь отправки (pgmq + cron), логирование, антиспам-список, страница отписки.

### 3. Auth-письма (брендирование)
Сгенерируются 6 React Email шаблонов (signup, recovery, magic-link, invite, email-change, reauthentication) с цветами и шрифтами проекта. Фон — белый.

### 4. Транзакционные шаблоны
В `src/lib/email-templates/` создадим два React Email шаблона:

- **`installment-created.tsx`** — «Ваша рассрочка оформлена». Поля: ФИО, товар, цена, взнос, срок, ежемесячный платёж, итог, дата первого платежа, кнопка «Открыть в личном кабинете».
- **`new-client-credentials.tsx`** — «Добро пожаловать + ваша рассрочка». То же содержимое + блок «Данные для входа: email / временный пароль» с рекомендацией сменить пароль.

Оба регистрируются в `registry.ts`.

### 5. Триггеры отправки

В `src/lib/admin.functions.ts` → `adminCreateInstallment`:
- если `client.kind === "new"` → отправить **`new-client-credentials`** на `data.client.email` с `templateData` (логин, пароль, поля рассрочки), `idempotencyKey = welcome-${clientId}`.
- если `client.kind === "existing"` → получить email клиента и отправить **`installment-created`**, `idempotencyKey = installment-${contract.id}`.

В `src/lib/installments.functions.ts` → `createInstallment` (самооформление клиентом): отправить **`installment-created`** на email текущего пользователя.

Отправка — серверная (через `supabaseAdmin` + service-role вызов к `/lovable/email/transactional/send`), чтобы письма уходили в т.ч. при self-signup без сессии.

## Что нужно от вас сейчас

1. Подтверждение на запуск настройки домена (откроется диалог).
2. Какой домен использовать для отправки (например `вашдомен.ru` → письма будут идти с `notify.вашдомен.ru`).

После подтверждения настрою домен, дождусь верификации не требуется для генерации шаблонов — статус будет виден в **Cloud → Emails**, а отправка включится автоматически после проверки DNS.
