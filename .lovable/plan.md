## Задача

Дать возможность при оформлении сделки с деньгами инвестора **сделать скидку клиенту, не уменьшая прибыль инвестора**. Сейчас прибыль инвестора считается как `markupAmount × profit_share_rate` — если снизить наценку ради скидки, инвестор автоматически теряет часть дохода.

## Идея

Ввести на каждой сделке отдельно фиксируемую **прибыль инвестора в рублях**. Она рассчитывается от «базовой» наценки (по договорной ставке инвестора) и «замораживается» на сделке. Дальше можно свободно уменьшать итоговую наценку для клиента — вычитаться будет только доля компании.

```text
Базовая наценка   = principal × baseRate × term        (по договору с инвестором)
Прибыль инвестора = базовая наценка × profit_share_rate  ← фиксируется на сделке
Фактическая наценка (для клиента) = редактируется вручную (можно ниже базовой)
Наша прибыль      = фактическая наценка − прибыль инвестора   (может быть 0 или отрицательной)
```

Компания сама решает, насколько «съесть» свою маржу ради скидки — инвестор всегда получит зафиксированную сумму.

## Что меняется

### 1. База данных (миграция)

В таблицу `installment_contracts` добавить два поля:
- `investor_profit_amount` — зафиксированная прибыль инвестора по этой сделке в ₽
- `investor_profit_locked` — флаг «прибыль зафиксирована вручную» (иначе считается динамически, как сейчас)

Оба поля опциональные, для старых сделок остаётся текущее поведение.

### 2. Форма новой рассрочки (`admin.installments.new.tsx`)

В блоке «Инвестор», когда выбран инвестор, добавить:
- поле **«Прибыль инвестора, ₽»** — предзаполняется от базовой ставки, можно менять
- переключатель **«Зафиксировать прибыль инвестора»** — по умолчанию включается автоматически, если пользователь трогает поле наценки или прибыли
- пересчитанные плашки:
  - Прибыль инвестора (зафиксирована) — жирным
  - Наша прибыль = фактическая наценка − прибыль инвестора (красным при отрицательной)
  - Подсказка «Скидка клиенту: X ₽» = базовая наценка − фактическая наценка

Ставку «наценка/мес» уже можно править — это и есть механизм скидки; ничего нового делать не нужно, только правильно посчитать распределение.

### 3. Серверная функция создания контракта

`createInstallmentContract` принимает и сохраняет `investor_profit_amount` + `investor_profit_locked`. Если флаг не выставлен, поля остаются `null` (обратная совместимость).

### 4. Отчёты и карточки

Везде, где сейчас считается `markup × profit_share_rate` (карточка инвестора, список сделок, аналитика, «Наша прибыль»), использовать зафиксированное значение при наличии; иначе — прежняя формула. Точки правки:
- `src/lib/investors.functions.ts` (агрегаты по инвестору)
- `src/lib/reports.functions.ts`
- Карточка контракта `admin.contracts.$id.tsx` — показать «Прибыль инвестора (зафиксирована)» + «Скидка клиенту»

### 5. Валидация

- `investor_profit_amount ≥ 0`
- Мягкое предупреждение (не блок), если `наша прибыль < 0` — «Сделка убыточна для компании, инвестор получит X ₽»
- Если инвестор не выбран — поле скрыто, поведение не меняется

## Что НЕ меняется

- График платежей клиента — считается от `total_sale_price`, как сейчас
- Договорная ставка `profit_share_rate` у инвестора — остаётся; используется только для предрасчёта
- Старые сделки — работают по прежней формуле
