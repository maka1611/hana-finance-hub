## Что меняется

Сейчас удаление клиентов и контрактов — **жёсткое** (`DELETE` из БД), восстановить невозможно и нельзя посмотреть кто/когда удалил. Переведём на **мягкое удаление** (soft delete) с архивом и восстановлением.

## 1. База данных (миграция)

Добавим в таблицы поля архивации:

- `profiles`: `deleted_at timestamptz`, `deleted_by uuid`, `deleted_reason text`
- `installment_contracts`: `deleted_at`, `deleted_by`, `deleted_reason` (плюс уже есть `status='completed'` — это «завершённый», его не трогаем)
- Каскад: при удалении клиента помечаем `deleted_at` у его контрактов автоматически

RLS/политики оставляем — фильтр по `deleted_at IS NULL` будет в server-функциях. Платежи, графики, заявки **не удаляем** физически (как сейчас), они остаются привязаны и видны после восстановления.

## 2. Server-функции (`src/lib/admin.functions.ts`)

- `adminDeleteClient` — переписать: вместо `DELETE` ставит `deleted_at=now()`, `deleted_by=auth.uid()` на `profiles` и каскадно на контракты клиента. Запись в `admin_audit_log`.
- `adminDeleteContract` (новая или переименование текущей) — soft delete контракта.
- `adminRestoreClient({ id })` — только для `owner`: снимает `deleted_at` с профиля и (опционально) с его контрактов.
- `adminRestoreContract({ id })` — только для `owner`.
- `adminListDeletedClients()` — список архивных клиентов с `deleted_at`, `deleted_by` (+ имя/email того, кто удалил).
- `adminListDeletedContracts()` — список архивных + завершённых контрактов.
- `adminListClients` / `adminListContracts` — добавить параметр `includeDeleted?: boolean`, по умолчанию `false` (фильтр `deleted_at IS NULL`).
- В `adminGetClient` / контрактные геттеры — возвращать `deleted_at`, `deleted_by`, имя удалившего (для отображения в карточке).

## 3. UI

### Поиск клиентов (`admin.clients.index.tsx`)
- Рядом со строкой поиска — переключатель/кнопка **«Показать удалённых»**. При активации вызывается `adminListClients({ includeDeleted: true })`, в таблице добавляется колонка «Удалён» (дата + кто), строки архивных — серым. Для `owner` — кнопка «Восстановить».

### Поиск контрактов (`admin.contracts.index.tsx`)
- Аналогично: кнопка **«Показать удалённые / завершённые»**, колонка статуса показывает `Удалён DD.MM.YYYY (Имя)` или `Завершён`. Для `owner` — «Восстановить» у удалённых.

### Карточка клиента / контракта
- Если запись архивная — баннер сверху: «Удалён 03.06.2026 пользователем Иван Иванов. Причина: ...» + кнопка «Восстановить» (только owner).
- В обычном режиме просмотра ничего не меняется.

### Боковое меню админа (`AdminSidebar.tsx`)
- Не добавляем отдельные пункты «Удалённые …» — доступ через переключатели в поиске (как просил пользователь). Если захотите отдельные разделы — скажите, добавим.

## 4. Что ещё стоит архивировать (предложение)

Помимо клиентов и контрактов, по той же схеме можно сделать мягкое удаление и восстановление для:

- **Заявок на рассрочку** (`installment_applications`) — сейчас удаляются вместе с клиентом; стоит хранить отдельно.
- **Инвесторов** (`investors`) — там уже есть `is_active`, можно расширить до `deleted_at`/восстановления.
- **Заявок инвесторов** (`investor_applications`).
- **Поручителей** (`contract_guarantors`).

Если хотите — включу их в эту же итерацию. Иначе сделаем только клиентов и контракты, остальное — отдельной задачей.

## 5. Права

- Удалять (мягко) — `manager/admin/owner` (как сейчас).
- Видеть «Удалённых» — любой staff.
- **Восстанавливать — только `owner`** (как вы просили «восстановление владельцем»).
- В `admin_audit_log` пишем оба события: `client.deleted`, `client.restored`, `contract.deleted`, `contract.restored`.

## Технические детали

- Миграция добавит колонки + индексы `WHERE deleted_at IS NOT NULL` для быстрой выборки архивных.
- Все существующие запросы (`adminListClients`, payments, dashboards, аналитика) получат `.is('deleted_at', null)` чтобы архивные не попадали в общую статистику.
- Тип `app_role` уже содержит `owner` — проверка через `has_role(auth.uid(), 'owner')`.
