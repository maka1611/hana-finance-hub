## Что добавить в аналитику

Сейчас на странице `/admin/analytics` показывается только общая маржа (`totalMarkup`) и денежные потоки без разделения по источнику капитала. Контракты уже содержат `investor_id` (NULL = свои средства), а у инвестора есть `profit_share_rate` (доля инвестора в наценке). Из этих данных можно посчитать полную раскладку.

### Новые показатели

Для каждого контракта:
- если `investor_id IS NULL` → вся наценка = **прибыль компании со своих средств**
- иначе → наценка делится:
  - **прибыль инвестора** = `markup_amount × profit_share_rate`
  - **прибыль компании с инвесторских средств** = `markup_amount × (1 − profit_share_rate)`

Из этого получаем агрегаты (всего и за выбранный период):
- Капитал в обороте: свой / инвесторский / суммарный
- Ожидаемая наценка: своя / с инвесторских / прибыль инвесторов / итого
- Фактически собранная наценка (на основе оплаченных платежей, пропорционально доле наценки в контракте): те же 3 разбиения
- Доля инвесторского капитала в портфеле (%)
- Топ-инвесторы по ожидаемой и полученной прибыли

### Изменения в UI (`src/routes/_authenticated/admin/analytics.tsx`)

Добавить три новых блока выше существующих графиков:

1. **«Структура капитала»** — карточки: «Свои средства», «Средства инвесторов», «Доля инвесторов, %», «Активных инвесторов».
2. **«Прибыль — раскладка»** — четыре карточки в одном блоке:
   - Наша прибыль (свои средства)
   - Наша прибыль (со средств инвесторов)
   - Итого наша прибыль
   - Прибыль инвесторов
   Под каждой — «ожидается» и «уже получено» мелким шрифтом + прогресс-бар (получено / ожидается).
3. **«Топ инвесторов»** — компактная таблица: ФИО, капитал, доля %, ожидаемая прибыль, полученная прибыль, прибыль компании от его средств.

Существующие KPI и график динамики сохраняются. В блок «Динамика» добавить в `totals` четыре числа за период: своя прибыль, прибыль с инвесторских, прибыль инвесторов, итого наша.

### Изменения в серверной логике (`src/lib/admin.functions.ts`)

1. `adminStats` — расширить запрос контрактов (`investor_id`) и подтянуть `investors(profit_share_rate, full_name, total_capital, is_active)`. Подгрузить `payments` с `contract_id`. Вернуть дополнительно:
   ```
   capital: { own, investor, total, investorShare }
   profitExpected: { own, companyFromInvestor, investors, companyTotal }
   profitCollected: { own, companyFromInvestor, investors, companyTotal }
   investorsActive: number
   topInvestors: Array<{ id, name, capital, shareRate, expectedProfit, receivedProfit, companyProfit }>
   ```
   Полученная прибыль на контракт = `paidSum × (markup_amount / total_sale_price)` (пропорциональная разнесение оплат на тело/наценку), затем делится по `shareRate`.

2. `adminAnalyticsSeries` — добавить в выгрузку контрактов `investor_id` + загрузить таблицу `investors` один раз, посчитать на каждый контракт `companyOwnProfit / companyInvestorProfit / investorProfit` и для платежей разнести их по дате контракта-источника. В `chart` и `totals` появятся ключи `profitOwn`, `profitCompanyFromInvestor`, `profitInvestors`, `profitCompanyTotal`. На графике добавим тонкую линию «Наша прибыль» (опционально, тем же визуальным стилем).

### Технические детали

- Доли считаются на момент чтения по текущему `profit_share_rate` инвестора (как и сейчас в кабинете инвестора — консистентно с `investor-portal.functions.ts`).
- Платежи разносятся по контракту: получаем `paidByContract` и долю наценки `markupShare = markup_amount / total_sale_price`. Это та же модель, что уже используется в `investor-portal.functions.ts`.
- Никаких изменений схемы БД и миграций не требуется.
- Никаких новых зависимостей.
