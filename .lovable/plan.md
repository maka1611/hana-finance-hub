# Понятная финансовая картина в кабинете инвестора

Цель: инвестор сразу видит, **сколько он вложил, сколько уже получил чистой прибыли, сколько ещё придёт и сколько будет у него на руках после погашения всех рассрочек** — с разбивкой по каждому платежу.

## Что меняется в данных (`src/lib/investor-portal.functions.ts`)

Расширяем `getMyInvestorDashboard`. Расчёты идут по уже известной формуле:
для каждого контракта `markupShare = markup_amount / (principal + markup_amount)`,
доля инвестора в платеже = `amount * markupShare * profit_share_rate` (прибыль),
возврат тела = `amount * (1 - markupShare)`.

Добавляем в ответ:

- `summary.totals`:
  - `principalReturnedToDate` — сколько тела уже вернулось
  - `principalRemaining` — сколько тела ещё в обороте (по графику будущих платежей)
  - `profitRemaining` — ожидаемая прибыль по ещё не оплаченным платежам
  - `totalPayout` — итог «на руках после всех платежей» = `capital + expectedProfitTotal` (с учётом ставки доли)
  - `progressPct` — процент уже полученной прибыли от общей ожидаемой
- По каждому контракту (`contracts[]`):
  - `investorPrincipal`, `investorProfitTotal` (его доля от markup),
  - `investorReceivedProfit`, `investorRemainingProfit`,
  - `investorReceivedPrincipal`, `investorRemainingPrincipal`,
  - `investorPayoutTotal` = principal + его доля прибыли
- `upcoming[]` — для каждого будущего платежа добавляем:
  - `principalPart`, `profitPartFull`, `investorProfit` (его чистая прибыль с этого платежа),
  - `investorCashflow` = principalPart + investorProfit (сколько «прилетит» инвестору)
- Новый блок `monthlyProjection[]` — агрегаты по месяцам на горизонте до конца самого длинного контракта: `month`, `investorPrincipal`, `investorProfit`, `investorTotal`, `cumulativeTotal` (для графика «как растёт капитал»).
- В `feed` для событий типа `payment` добавляем `investorProfit` и `investorPrincipal`, чтобы в ленте было видно «из них ваша чистая прибыль: X ₽».

Расчёт `monthsActive` для средней доходности оставляем, но переименовываем подпись в UI на «Средняя чистая доходность / мес», чтобы было однозначно.

## Что меняется в UI (`src/routes/_authenticated/app.investor.tsx`)

1. **Блок «Сводка по деньгам»** — заменяем 4 карточки на более информативные:
   - Капитал (вложено)
   - Получено прибыли / Ожидается ещё (с прогресс-баром `progressPct`)
   - Итог после всех платежей (`totalPayout`) + подсказка «капитал + чистая прибыль»
   - Средняя чистая доходность / мес, % годовых (производное `*12`)

2. **Таблица «Активные рассрочки»** — добавляем колонки:
   - «Ваша прибыль» (итого по контракту)
   - «Уже получено / осталось» (двумя строчками в ячейке)
   - «Итого к получению» (principal + profit)
   Прогресс `paidCount / totalCount` оставляем.

3. **Таблица «Ближайшие поступления»** — переименовываем заголовок в «Ближайшие поступления и ваша прибыль» и добавляем колонки:
   - «Возврат тела»
   - «Чистая прибыль» (зелёным)
   - «Ваш приход» (сумма)
   Внизу — строка ИТОГО за 90 дней.

4. **Новая секция «Прогноз по месяцам»** — компактная таблица (или простой stacked-bar на CSS) из `monthlyProjection`:
   `Месяц | Возврат тела | Чистая прибыль | Всего | Накопительно`. Сразу видно, к какой дате капитал полностью отработает.

5. **Лента событий** — для платежей добавляем мелкую строку «из них чистая прибыль: +X ₽» под суммой.

Цвета/токены — как уже используются (emerald для прибыли, red для выводов/просрочек, semantic tokens из `src/styles.css`). Никаких изменений в БД, RLS, email-шаблонах, серверных функциях создания контрактов. Данные клиентов по-прежнему обезличены.

## Технические детали

- Все новые числа считаются на сервере в `getMyInvestorDashboard` — компонент остаётся «тонким».
- Для `monthlyProjection` берём все `payment_schedules` (включая уже оплаченные — для накопительного итога) и группируем по `YYYY-MM` от `due_date`.
- TypeScript-типы возвращаемого объекта обновляем; правок в `routeTree.gen.ts`/миграций не требуется.
