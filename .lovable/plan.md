## Как инвестор попадает в свой кабинет

Связка по email: если `profiles.email` совпадает с `investors.email` (и `investors.is_active = true`), пользователь видит в сайдбаре новый пункт **«Инвестор»**. Никаких новых ролей и колонок — админ просто заводит инвестора с тем email, под которым клиент регистрируется.

## Раздел «Инвестор» (`/app/investor`)

Read-only страница для авторизованного пользователя-инвестора. Все данные грузятся через серверную функцию `getMyInvestorDashboard` (под `requireSupabaseAuth`), которая внутри сама находит запись `investors` по email текущего пользователя. Если совпадения нет — 404.

### 1. Сводка (карточки сверху)
- Капитал (`total_capital`)
- Размещено в рассрочках / Свободные средства
- Доля прибыли (%) и капитализация (вкл/выкл)
- Ожидаемая прибыль по активным договорам (его доля)
- Полученная прибыль (его доля от уже выплаченных платежей)
- Средняя месячная доходность: `полученная прибыль / месяцев с первого взноса / капитал × 100%`
- Просрочки: количество и сумма (без указания клиентов)

### 2. Активные рассрочки на его средства
Таблица контрактов с `investor_id = его id`. Колонки:
- Товар, сумма (principal), наценка, срок, ежемесячный платёж, дата старта, статус, прогресс выплат (X / Y).
- **Без ФИО, телефона, email клиента** — только обезличенный ID вида `Клиент #ab12` (первые 4 символа `client_id`) по согласованному требованию не раскрывать клиентов инвестору.

### 3. График ближайших поступлений
Список `payment_schedules` по его контрактам на 90 дней вперёд + просрочки. Дата, сумма, статус. Без клиента.

### 4. История взносов и выводов
`investor_contributions` по убыванию даты: дата операции, сумма (+ зелёный для взноса, − красный для вывода), срок, комментарий.

### 5. Лента уведомлений
Простая лента событий, склеенная из:
- «Новая рассрочка на ваши средства» — каждый контракт с investor_id (по `created_at`).
- «Поступил платёж» — записи `payments` по его контрактам.
- «Внесён/выведен капитал» — записи `investor_contributions`.

Без отдельной таблицы уведомлений — это просто отсортированная по времени выборка из существующих данных.

## Email-уведомление при оформлении новой рассрочки

Новый transactional-шаблон `installment-funded-by-investor`:
- Тема: «Новая рассрочка профинансирована вашими средствами».
- Содержание: товар, сумма principal, срок, ежемесячный платёж, дата старта, ваша доля прибыли по этому договору, ссылка на кабинет `/app/investor`. **Без данных клиента.**

Триггер — внутри обеих серверных функций создания контракта:
- `adminCreateInstallment` в `admin.functions.ts`
- `createInstallment` в `installments.functions.ts`

После успешной вставки контракта: если у контракта есть `investor_id` — подтянуть `investors.email`, и поставить письмо в очередь через `send-transactional-email` с `idempotencyKey = investor-funded-${contract.id}` (защита от дубля при повторе). При смене `investor_id` через `setContractInvestor` — тоже отправлять (idempotencyKey тот же, поэтому повторов не будет).

Доставка идёт через уже настроенную инфраструктуру `notify.noorpay.ru`.

## Безопасность доступа

- Серверная функция сама определяет инвестора по email → клиент не может подсунуть чужой `investor_id`.
- Запросы идут через `supabaseAdmin` строго с фильтром по найденному `investor_id`.
- RLS не трогаем — `investors`, `installment_contracts`, `payment_schedules` остаются с текущей staff-политикой; чтение происходит на сервере.

## Технические детали

**Новые/изменённые файлы:**
- `src/lib/investor-portal.functions.ts` — `getMyInvestorDashboard()`: ищет investor по email, возвращает summary, контракты (без клиентских полей), 90-дневный график, contributions, ленту событий.
- `src/routes/_authenticated/app.investor.tsx` — страница раздела (карточки + 4 таба или секции).
- `src/components/client/ClientSidebar.tsx` — пункт «Инвестор» (видим, если в context приходит `isInvestor: true`).
- `src/routes/_authenticated/app.tsx` — добавить в loader/контекст флаг `isInvestor` (проверка совпадения email с `investors`).
- `src/lib/email-templates/installment-funded-by-investor.tsx` + регистрация в `registry.ts`.
- `src/lib/admin.functions.ts` и `src/lib/installments.functions.ts` — после создания контракта вызвать отправку письма, если есть `investor_id`.

**Никаких миграций БД не требуется** — все нужные таблицы и поля уже есть.

## Что НЕ делаем
- Не раскрываем ФИО/контакты клиентов инвестору (по вашему уточнению).
- Не делаем отдельную роль `investor` и не прячем клиентские разделы — инвестор остаётся обычным пользователем с дополнительной вкладкой.
- Не вводим отдельную таблицу уведомлений — лента строится из существующих данных.
